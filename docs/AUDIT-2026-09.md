persistence and migrations, offline, audio, every screen on a phone, dependencies,

fixed it; judgement calls are at the end as recommendations.

Severity: **High** loses or misstates the player's data or blocks practice.
**Medium** is visibly wrong. **Low** is noise or a maintenance hazard.

### Test suite rot, fixed

The browser suites had been drifting; failures that were the test, not the app:

- `chunkFailure` looked for a Coached button on an account with no measured history, which the app deliberately does not offer (`3219ca0`).
- `coached` used fixed August dates that aged into the tempo planner's "back after a break" rule (`50a517c`).
- `coverage` held empty panels to 40 characters of prose, which the drawn empty states replaced; `midnight` seeded a two-block task, which now loads as two tasks (`02ae1ac`).
- `scale` and `songTiming` performance budgets took one wall-clock sample; on this shared VPS the same build measured 35–103 ms. Now the fastest of five, budgets unchanged (`ca84be3`).
- `tuner` crashed on hosts where WebKit cannot launch (no GTK/GStreamer on the VPS); it now runs Chromium and reports the skip (`2166d60`).

## Checked and sound

- **Streaks, XP, awards.** The flame streak and XP's "longest run" were read
  against `completedSet`, so a completed combined task counts for every part.
  Past days are never rewritten. XP replays drill results, which are keyed by
  chord pair (`pair:A|D`), not by task, so per-pair history is continuous across
  the split. (Verified: `tests/xp.test.mjs`, `tests/taskSplitStore.test.mjs`.)
- **Midnight during a session.** Already pinned by `tests/browser/midnight.mjs`;
  still green after the split.
- **Sync.** Last-write-wins on `updatedAt` is preserved; the migration leaves
  `updatedAt` alone so it can never win a race it did not enter. Split maps are
  unioned across devices, append-only.
- **Persistence failure.** `store/persistence.ts` surfaces a full disk as "Not

- **Offline.** 73 precached entries (2.5 MB); `offline` suite green; coach clips
  runtime-cached.
- **Audio lifecycle.** Mic tracks are stopped and contexts closed on every exit
  path (`micStream.stop`); `micLost` and `micDenied` suites green.
- **Every screen at 390×844** with the owner's own export: home, Quick sheet,
  tuner, note circle, the four Progress tabs, Chord Perfect, a timed task, a song,
  the coached intro, quick setup, settings, add task, the task menu. No sideways
  scroll, no overlaps, no console errors.

## Recommendations (judgement calls, not changed)

1. **Two different streaks.** The flame on the home screen counts any day with a
   ticked task; Awards' "longest run" counts only days the app heard playing.
   Both are defensible, and they will disagree after a day of timers only. Pick
   one meaning, or label the flame "days practised".
2. **Entry bundle, 740 kB (218 kB gzip).** Measured by source: `react-dom`
   dominates, then the Radix context menu with Floating UI (about 130 kB raw,
   only for the long-press task menu), framer-motion, and the app's own home
   screen. Lazy-loading the context menu is the one cheap win. Not done here
   because it changes how the menu opens on first long-press.
3. **Held major upgrades.** TypeScript 7, framer-motion 13 and @types/node 26
   are out. Each is a separate, testable change; none carries a security fix.
4. **Coach voice clips for new task names.** Split changes parts are announced
   by their exercise name, which has a clip. New block titles you add later get
   the generic "Up next" until `npm run names && npm run gen:voice` is re-run.
5. **WebKit coverage.** Resolved on 2 October 2026: WebKit now runs on the VPS
   (see the addendum below).

## Addendum, 2 October 2026: Safari checked without the Mac

Acarson's standing rule is now that no step depends on his Mac. Safari is
checked on the VPS with Playwright WebKit, using an iPhone profile.

- **Installed WebKit's system libraries** on the VPS
  (`npx playwright install-deps webkit`). Before this, WebKit could not launch
  there and the tuner suite skipped its Safari half.
- **`tests/browser/engine.mjs`** (new). `BROWSER=webkit` runs `quickPaths` and
  `layout` as an iPhone. `npm run health -- --live` checks the live site in
  both engines (20 checks), and `--browser` runs those suites in both engines.
  The layout suite now includes 820×1180.
- **Fixed: on a touch screen at 360 wide, only one whole task fit.** Only the
  WebKit iPhone run caught this, because Chromium's run never emulated touch.
  Two touch rules made the screen 15px taller in total. The task row's go button
  grew from 26 to 32px, adding 6px to every row. The "Add quick task" target
  grew to 44px, adding 9px to the footer. Both tap targets keep their size: the
  go button takes its extra height out of the row's padding, and the footer
  gives back its padding. Two rows fit again at 360. Checked in both engines at
  all ten viewports, with a screenshot.
- **Tuner suite in WebKit.** The app was fine; three test-harness problems were
  fixed:
  - "Audio is paused" was read once, after a fixed 1.5s. It now waits up to 8s
    for the start-up to settle.
  - The stand-in microphone's context could be garbage-collected, which ended
    its track. The context is now kept alive, and if headless WebKit still ends
    the track under load, the run says so and runs the case again.
  - The cents reading was taken from the first number on screen. It now uses
    the middle of two seconds of readings.
- **Quick paths passes in WebKit** against the live site and a local build. So
  does the tuner's whole Safari half, including the refused audio route, all
  four microphone refusals and a stalled code chunk.
